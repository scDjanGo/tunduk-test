# Candidate Dashboard

Дашборд для HR-специалиста: список кандидатов с фильтрацией/поиском/сортировкой, детальная карточка кандидата с критериями оценки и вопросами для собеседования, управление статусом обработки резюме с оптимистичным обновлением UI.

Тестовое задание на позицию **React Middle** (CV-Scan).

## Стек

- **React 19** + **TypeScript**
- **Vite** — сборка и dev-сервер
- **Redux Toolkit** + **react-redux** — state management (кандидаты, фильтры)
- **React Router v7** — маршрутизация, синхронизация фильтров с URL
- **Tailwind CSS v4** — стилизация, адаптивная вёрстка
- **@tanstack/react-virtual** — виртуализация списка
- **Vitest** + **React Testing Library** + **jsdom** — тестирование

## Запуск

```bash
npm install
npm run dev          # дев-сервер (http://localhost:5173)
npm run build        # типизация (tsc -b) + продакшен-сборка
npm run lint          # ESLint
npm run test          # тесты в watch-режиме
npm run test:run      # тесты одним прогоном
npm run test:coverage # тесты + отчёт о покрытии
```

## Реализованные задания

### 1. Список кандидатов
Таблица с адаптивной вёрсткой (десктоп/мобайл рендерятся в одном `<tr>`, переключение через Tailwind `hidden`/`table-cell`, чтобы не плодить дублирующиеся доступные элементы). Фильтр по вердикту, поиск по ФИО с debounce 300 мс, сортировка по имени/опыту/дате, пагинация по 10 элементов. Все фильтры синхронизированы с query-параметрами URL — состояние переживает рефреш и доступно по прямой ссылке.

### 2. Детальная карточка
Маршрут `/candidate/:id`, разбит на подкомпоненты (`ContactInfo`, `ExperienceSection`, `CriteriaSection`, `StatusSelect`). 404, если кандидат не найден (в том числе при прямом заходе по ссылке до того, как список успел загрузиться). Кнопка «Назад» возвращает с сохранёнными фильтрами.

### 3. Управление статусами
Выпадающий список статуса с оптимистичным обновлением: UI меняется мгновенно, запрос (мок `PATCH`) уходит в фоне, при ошибке — откат к предыдущему статусу и toast с сообщением об ошибке. Во время запроса показывается loading-индикатор на селекте.

### 4. Тестирование
106 тестов, покрытие: **99.4% statements / 88.9% branches / 99.1% functions / 99.6% lines** (`npm run test:coverage`). Покрыты: фильтрация по вердикту, поиск с debounce, цветовая индикация вердикта, переход список → детальная страница (клик и клавиатура), оптимистичное обновление статуса с роллбэком, edge cases (пустой список, ошибка загрузки, пагинация на границах, склонение слова «кандидат»).

### 5. Оптимизация (большой датасет)
Переключатель датасета (25 / 120 кандидатов) поверх `mock/candidates-large.json`. Фильтрация и сортировка мемоизированы через `createSelector` (Redux Toolkit) — пересчитываются только при реальном изменении входных данных. `CandidateCard` обёрнут в `React.memo`. В список добавлена виртуализация (`@tanstack/react-virtual`).

> **Компромисс по виртуализации**: при текущем `PAGE_SIZE = 10` виртуализация не даёт заметного эффекта — пагинация и так ограничивает DOM десятью строками. Решил оставить её как архитектурный задел: если `PAGE_SIZE` увеличить (или переключить на бесконечный скролл), список из 120+ строк продолжит рендерить только видимое окно без изменений в коде. Альтернатива — убрать пагинацию и отдать всю работу виртуализации — была обсуждена и отклонена в пользу текущего поведения (пагинация привычнее для HR-сценария и проще тестируется).

## Принятые решения

- **Redux Toolkit вместо Zustand** — нормализация и `createSelector` показались уместнее для связки «список + фильтры + URL», плюс более явная трассировка состояния в DevTools.
- **Один `<tr>` на кандидата с CSS-переключением десктоп/мобайл-ячеек**, а не два разных дерева/компонента — упрощает доступность (один `role="button"` на строку вместо дублирующихся) за счёт небольшого избытка в DOM.
- **Debounce поиска через `useDebounce` + локальный `useState`** в `SearchBar`, а не дебаунс прямо в санке/селекторе — инпут остаётся отзывчивым (controlled value меняется сразу), в Redux летит только финальное значение.
- **`useRef` вместо доп. состояния** для once-эффектов (инициализация фильтров из URL, защита от повторной загрузки кандидата на детальной странице) — избегает лишних ререндеров.

## Что не успел / осталось за скобками

- Code-splitting: продакшен-бандл ~540 кБ (выше дефолтного порога предупреждения Vite). Для проекта такого размера не показалось критичным, но в реальном продукте стоило бы вынести страницы через `React.lazy`.
- React Query не использовался — для мок-API с двумя эндпоинтами Redux Toolkit thunks показались достаточными без добавления второй системы кеширования.
- Анимации/переходы между состояниями — сделана только базовая `transition-colors` на интерактивных элементах.
